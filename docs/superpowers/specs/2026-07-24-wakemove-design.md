# WakeMove 产品与技术设计

- 日期：2026-07-24
- 状态：已确认
- 项目目录：`D:\WakeMove`
- 首版平台：Android 10+、Windows 10/11 64 位
- 首版语言：简体中文

## 1. 产品目标

WakeMove 是一款需要完成身体动作或说出随机口令才能关闭的本地闹钟应用。首版同时提供 Android 应用和 Windows 桌面程序，并优先保证闹钟调度、后台响铃和挑战验证的可靠性。

成功标准如下：

1. 用户可创建常规重复闹钟，并为每个闹钟选择一种关闭挑战。
2. Android 在锁屏或应用退出后仍能按时响铃。
3. Windows 窗口关闭后程序继续驻留系统托盘并按时响铃。
4. 用户完成指定动作或正确说出随机短句后，闹钟才会停止。
5. 权限、硬件或网络异常不会导致闹钟永久无法关闭。
6. 摄像头画面和 WakeMove 收到的麦克风音频不被应用保存或上传。

## 2. 首版范围

### 2.1 闹钟功能

每个闹钟支持：

- 时间；
- 名称；
- 按星期重复；
- 启用或停用；
- 铃声；
- Android 振动；
- 稍后提醒间隔；
- 稍后提醒次数上限；
- 一种关闭挑战；
- 动作目标次数。

“稍后提醒”不要求先完成挑战，默认间隔为 5 分钟，每次响铃最多使用 3 次。用户达到上限后只能完成挑战或使用异常情况下的紧急停止。

### 2.2 关闭挑战

首版提供四种挑战：

1. 深蹲：默认 5 次；
2. 开合跳：默认 5 次；
3. 双手举起：双手保持在头部上方 2 秒；
4. 随机语音短句：正确说出屏幕显示的简体中文短句。

用户在创建或编辑闹钟时选择一种挑战，并设置动作次数。语音挑战不设置次数，每次响铃随机选择一条口令。

### 2.3 本地历史和健康检查

历史记录包含：

- 计划响铃时间；
- 实际响铃时间；
- 成功完成时间；
- 挑战类型；
- 稍后提醒次数；
- 成功、紧急绕过或错过状态。

健康检查页面显示：

- 系统通知权限；
- 精确闹钟权限；
- 全屏响铃权限；
- 摄像头和麦克风权限；
- Android 电池优化提示；
- Windows 托盘和开机启动状态；
- 最近一次调度结果；
- 下一个已注册闹钟。

## 4. 总体架构

项目采用单 Git 仓库、双客户端结构：

```text
D:\WakeMove\
├─ android\       Kotlin + Jetpack Compose 原生 Android 应用
├─ desktop\       Tauri + React + TypeScript + Rust Windows 应用
├─ shared\        口令、动作规则、图标和视觉规范
└─ docs\          产品、技术、权限和测试文档
```

两个客户端分别保存本地数据，不进行同步。`shared` 只保存可以跨语言消费的静态资源和规范，例如 JSON 口令列表、动作定义、图标及设计令牌；它不强行共享平台业务代码。

### 4.1 Android

- Kotlin；
- Jetpack Compose；
- Room；
- AlarmManager；
- 前台服务；
- BroadcastReceiver；
- CameraX；
- MediaPipe Pose Landmarker；
- Android SpeechRecognizer；
- MediaPlayer 或 ExoPlayer 兼容的本地铃声播放层。

AlarmManager 负责系统级调度。响铃时启动前台服务维持声音与振动，并展示全屏响铃界面。系统重启、时区变化、应用升级或闹钟编辑后重新计算并注册下一次闹钟。

### 4.2 Windows

- Tauri；
- React；
- TypeScript；
- Rust；
- SQLite；
- MediaPipe Web；
- Windows 原生语音识别桥接；
- 系统托盘、开机启动、通知和单实例控制。

React 负责界面与动作挑战视图。Rust 负责本地数据库、后台调度、托盘生命周期、音频会话、系统通知、开机启动和 Windows API 桥接。关闭主窗口只隐藏到托盘；用户通过托盘明确选择“退出”时才结束程序，并看到“退出后闹钟不会响”的确认。

## 5. 模块边界

### 5.1 Alarm Repository

负责闹钟、设置、历史和活动会话的持久化。上层只通过仓库接口读写数据，不依赖 Room 或 SQLite 的具体实现。

### 5.2 Schedule Calculator

输入闹钟、当前本地时间和时区，输出下一次计划响铃时间。它是纯业务模块，负责星期重复、跨午夜、夏令时和稍后提醒计算，不直接调用系统调度 API。

### 5.3 Platform Scheduler

将计算出的时间注册到平台：

- Android 使用 AlarmManager；
- Windows 使用 Rust 后台调度器。

调度器还负责取消、重排、开机恢复和时钟变化恢复。

### 5.4 Ringing Session

表示一次正在进行的响铃。它负责：

- 循环播放铃声；
- Android 振动；
- 展示全屏或置顶界面；
- 跟踪稍后提醒次数；
- 启动挑战；
- 在成功、稍后提醒或紧急停止后结束会话；
- 写入历史并安排下一个重复闹钟。

### 5.5 Challenge Engine

统一管理挑战状态，但将传感器和模型调用交给平台适配器。每个挑战通过明确接口暴露：

- 初始化；
- 权限与可用性检查；
- 进度事件；
- 成功事件；
- 可恢复错误；
- 不可用错误；
- 释放资源。

挑战实现之间互不依赖，可以单独测试和替换。

### 5.6 Permission and Health Service

汇总权限、后台能力和调度状态，并输出可操作的问题列表。界面不自行推断权限状态，只展示该服务的结果和修复入口。

## 6. 数据模型

### 6.1 Alarm

```text
id                  UUID
time                本地时分
label               字符串
enabled             布尔值
repeatDays          星期集合
soundId             铃声标识
vibrationEnabled    布尔值
snoozeMinutes       正整数，默认 5
snoozeLimit         非负整数，默认 3
challengeType       SQUAT | JUMPING_JACK | HANDS_UP | VOICE_PHRASE
targetCount         动作次数；语音挑战固定为 1
createdAt           时间戳
updatedAt           时间戳
```

### 6.2 RingingSession

```text
id                  UUID
alarmId             UUID
scheduledAt         时间戳
startedAt           时间戳
snoozeCount         非负整数
challengeType       挑战类型快照
targetCount         目标快照
status              RINGING | SNOOZED | COMPLETED | BYPASSED | MISSED
```

保存挑战快照可避免用户在响铃过程中编辑原闹钟而改变当前要求。

### 6.3 AlarmEvent

```text
id                  UUID
alarmId             UUID
scheduledAt         时间戳
startedAt           可空时间戳
finishedAt          可空时间戳
challengeType       挑战类型
snoozeCount         非负整数
result              COMPLETED | BYPASSED | MISSED
```

## 7. 运行流程

### 7.1 创建或编辑

1. 用户填写时间、重复、铃声、振动、稍后提醒和挑战。
2. 应用验证字段和必需权限。
3. Alarm Repository 保存数据。
4. Schedule Calculator 计算下一次时间。
5. Platform Scheduler 注册系统任务。
6. 健康检查更新并显示下一次闹钟。

### 7.2 响铃

1. 平台调度器触发。
2. 应用创建或恢复 RingingSession。
3. 铃声开始循环；Android 同时振动。
4. 应用展示 Android 全屏界面或 Windows 置顶窗口。
5. 用户可稍后提醒，或主动开始挑战。
6. 开始挑战后才申请并使用摄像头或麦克风。
7. Challenge Engine 持续输出进度。
8. 达到目标后停止声音和振动，记录成功结果。
9. 重复闹钟计算并注册下一次时间；单次闹钟自动停用。

### 7.3 稍后提醒

1. 若次数未达到上限，结束当前声音和传感器会话。
2. RingingSession 递增稍后提醒次数。
3. Platform Scheduler 注册新的稍后提醒时间。
4. 达到上限后隐藏稍后提醒按钮。

## 8. 动作与语音识别

### 8.1 通用动作规则

MediaPipe 只产生人体关键点坐标。WakeMove 的动作状态机基于归一化角度和相对位置判断动作，不保存图像帧。

- 深蹲：稳定站立、下蹲达到膝髋角阈值、重新站立才计为一次。
- 开合跳：手臂放下且双脚并拢、手臂抬高且双脚分开、回到起始姿势才计为一次。
- 双手举起：左右手腕均高于头部关键点并连续保持 2 秒。

状态机加入稳定帧数、动作冷却时间和置信度门槛，防止关键点抖动或半个动作重复计数。界面实时显示当前计数、人体轮廓提示、距离提示和光线提示。

### 8.2 语音口令

随机短句来自随安装包发布的简体中文口令列表。识别结果统一执行：

- 去除空格和标点；
- 中文数字和阿拉伯数字规范化；
- 全角和半角字符规范化；
- 对系统返回的候选结果逐一匹配。

只有规范化后的完整短句匹配时才通过。Android 调用系统 SpeechRecognizer；Windows 通过 Rust 原生桥接调用 Windows 语音识别能力。系统服务可能联网，但 WakeMove 不持有第三方云服务密钥，也不保存音频。

## 9. 异常处理与可靠性

### 9.1 挑战不可用

- 光线不足或人物未完整入镜：显示明确指导，不累计错误动作。
- 动作挑战连续 60 秒未完成：允许切换为随机语音口令。
- 语音服务断网或连续识别失败：允许切换为摄像头动作挑战。
- 摄像头和麦克风均不可用：显示权限修复入口，并提供按住 10 秒的紧急停止。
- 紧急停止写入 `BYPASSED` 历史，并在下次进入应用时强提示修复。

### 9.2 Android

- 缺少精确闹钟、通知或全屏显示权限时，闹钟不能被标记为健康状态；应用提供系统设置入口。
- 系统重启、时区改变和应用升级后重新注册所有已启用闹钟。
- 活动 RingingSession 先落盘，再启动声音和挑战；进程恢复后继续未结束会话。
- 无法阻止用户在系统设置中强制停止应用、关闭设备或撤销权限。健康检查对此作出明确说明。

### 9.3 Windows

- 默认启用开机启动并驻留托盘。
- 真正退出前必须确认，并明确提示退出后闹钟不会响。
- 从休眠恢复时，错过不超过 30 分钟的闹钟立即补响。
- 错过超过 30 分钟的闹钟记为 `MISSED` 并发送通知，不补响。
- “允许唤醒计时器”作为可选设置；实际唤醒能力受硬件、Windows 电源计划和管理员策略限制。
- 单实例锁防止多个进程重复触发同一闹钟。

## 10. 视觉与交互

视觉采用“日出活力”方向：

- 暖白和浅橙背景；

- 大号时间数字；
- 圆角卡片；
- 高对比响铃模式；
- 简体中文文案。

Android 使用底部导航，包含闹钟、历史和健康检查；设置从顶部入口进入。Windows 使用左侧导航，包含闹钟、历史、健康检查和设置，并显示托盘后台状态。

首版页面：

1. 首次启动和权限引导；
2. 闹钟列表；
3. 创建或编辑闹钟；
4. 全屏或置顶响铃；
5. 动作挑战；
6. 语音挑战；
7. 历史记录；
8. 健康检查；
9. 设置；
10. Windows 托盘菜单和退出确认。

挑战页面保持铃声状态可见，显示时间、闹钟名称、目标、当前进度、取景指导、剩余稍后提醒次数和备用挑战入口。普通关闭按钮不存在。

## 11. 隐私与权限

- 摄像头只在挑战期间启用。
- 动作识别在本机完成。
- WakeMove 不保存摄像头帧。
- WakeMove 不保存麦克风录音。
- 语音识别可能由 Android 或 Windows 系统服务联网完成，首次启用时明确告知。
- 健康检查会确认简体中文语音识别服务或语言包可用；不可用时引导用户安装或改用动作挑战。
- 所有闹钟、历史和设置仅保存在本机。
- 用户可以清除历史或全部本地数据。
- 权限请求采用按需方式，并在请求前解释用途。

## 13. 首版验收标准

1. 正常运行状态下，Android 与 Windows 在设定时间前后 3 秒内开始响铃。
2. Android 重启后、Windows 重新登录并自动启动后，已启用闹钟仍存在并重新调度。
3. 深蹲、开合跳和双手举起各完成 20 轮标准测试，至少 18 轮正确完成，静止或无关动作不能关闭闹钟。
4. 随机中文短句在安静联网环境下完成 20 轮测试，至少 18 轮正确识别，错误口令不能通过。
5. 摄像头、麦克风或网络不可用时，备用挑战和紧急停止均可工作。
6. 闹钟、历史和设置在应用或设备重启后保留。
7. 可本地安装的 Android APK 和 Windows EXE 安装程序能够构建，并通过全新安装、升级和卸载测试。
