## 2. 已确定的产品方向

WakeMove 是一个需要完成动作或语音挑战才能关闭的闹钟。

当前平台方向：

- Android 手机端
- Windows 10/11 桌面 EXE
- 不再开发网页端

Android 最低版本为 Android 10：

```text
applicationId = com.wakemove.android
minSdk = 29
targetSdk = 37
versionCode = 3
versionName = 1.2.0
```

中文上架名称仍未最终确定。曾倾向短、带行动感的名称，例如“醒动”，但尚未进行正式商标和应用商店重名核验。

## 3. Android 已完成内容

### 闹钟基础能力

- 创建、编辑、启用、停用和删除闹钟
- 一次性闹钟和按星期重复闹钟
- Android 精确闹钟调度
- 重启、重新授权精确闹钟后的恢复调度
- 闹钟前台服务、循环声音和振动
- 每个闹钟可独立选择 4 段 APK 内置原创舒缓铃声：晨风、朝露、静港、林间光
- 铃声可在编辑页直接试听；旧闹钟的默认铃声会自动映射到“晨风”
- 每个闹钟可独立选择舒缓、双拍、密集 3 种震动节奏，以及轻、中、强 3 档力度
- 震动选项支持即时试震；关闭震动后，节奏和力度设置仍会保留
- 全屏响铃界面
- 最多 3 次稍后提醒，默认间隔 5 分钟
- 稍后提醒在进程恢复、重启和重新授权后的持久化恢复
- 完成、紧急停止、错过等本地历史记录
- 通知、精确闹钟、全屏通知、摄像头和麦克风健康检查

### 关闭挑战

- 深蹲
- 开合跳
- 双手举高
- 随机简体中文语音短句
- CameraX + MediaPipe 本地人体关键点识别
- Vosk + 内置简体中文模型的离线语音识别，不依赖系统语音服务，也不联网下载模型
- 动作与语音不可用时的备用挑战流程
- 连续按住 10 秒的紧急停止

### 数据与架构

- Kotlin + Jetpack Compose + Material 3
- Room 本地数据库
- 纯 `ScheduleCalculator`
- Android `AlarmManager`
- `RingingSessionController`
- 摄像头、语音、调度、存储和界面模块已分离

主要源码目录：

```text
android/app/src/main/java/com/wakemove/android/
├─ challenge/     动作和语音识别
├─ data/          Room 数据库和 Repository

├─ health/        权限与系统健康检查
```

手动安装 Debug APK：

```powershell
$adb = 'C:\Users\13237\AppData\Local\Android\Sdk\platform-tools\adb.exe'
& $adb install -r 'D:\WakeMove\android\app\build\outputs\apk\debug\app-debug.apk'
& $adb shell monkey -p com.wakemove.android -c android.intent.category.LAUNCHER 1
```

Debug 和 Release 使用不同签名：

- 模拟器已有 Debug 版本时，可以用新的 Debug APK 覆盖安装。
- 不能直接用 Release APK 覆盖 Debug APK，会出现 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。
- 如果一定要换成 Release，需要先卸载旧版本，但会清除该模拟器内的 WakeMove 数据。

## 8. 开发过程中踩过的坑

### Android SDK 本地配置

新的 Git worktree 不会自动包含被忽略的 `android/local.properties`，缺少时 Gradle 会报：

```text
SDK location not found
```

本机配置应为：

```properties
sdk.dir=C\:\\Users\\13237\\AppData\\Local\\Android\\Sdk
```

`local.properties` 必须保持 Git 忽略状态。

### Release 签名配置

`android/keystore.properties` 和实际 keystore 是本地敏感文件，不会随 worktree 或 GitHub 自动复制。

- 构建 Release 前要确认本地配置存在。
- 不要在终端、报告或聊天中输出密码。
- 不要提交 keystore、密码或 `keystore.properties`。

### APK 签名冲突

模拟器曾残留 Debug 签名版本，安装 Release 时出现：

```text
INSTALL_FAILED_UPDATE_INCOMPATIBLE
```

已确认当时：

- 已安装版本证书 = 当前 Debug 证书
- Release 使用另一把证书

安全做法是继续覆盖安装 Debug；只有明确接受清除数据时才卸载后安装 Release。

### 模拟器未完整启动

曾出现：

- `Broken pipe`
- `Can't find service: package`
- `Activity never becomes DESTROYED`
- `sys.boot_completed` 为空
- system_server 等待缺失的 SurfaceFlinger

这不是产品代码错误，而是模拟器快照损坏或未完成启动。

处理方法：

1. 检查 `adb shell service check package` 和 `service check activity`。
2. 普通重启仍不正常时，对相同 AVD 执行 Cold Boot。
3. 必要时使用 `-no-snapshot-load -no-snapshot-save` 启动。
4. 服务恢复后再重跑失败测试，不要把基础设施故障误判为 App Bug。

### Compose 合并语义

父控件会合并子节点语义。测试选中对勾等子节点时，默认语义树可能找不到标签。

需要时使用：

```kotlin
useUnmergedTree = true
```

父控件的 `selected`、`Role.Checkbox` 等语义仍应在合并树中验证。

### 固定底部保存栏

改为固定底部按钮后：

- 旧测试不能再对保存按钮调用不必要的 `performScrollTo()`。
- 滚动内容必须留出底部空间。
- 自定义底部栏必须调用 `navigationBarsPadding()`。
- 必须在小屏和手势导航模式下检查内容不会被遮挡。

### 颜色对比度

原始亮橙色 `#FF7A1A` 放在桃色或白色上时，对比度不足。

已增加深焦橙：

```text
#A33A00
```

用于选中的导航文字/图标以及挑战卡边框/对勾。后续新增配色必须测试真实前景与真实背景，而不是只测试主题里未实际使用的颜色组合。

### 调度规则与展示规则不能重复

最终审查发现：调度器会把“不是今天创建/更新的一次性闹钟”标记为错过，但首页曾可能继续把它显示为下一次唤醒。

已将该资格规则集中到 `ScheduleCalculator.nextOccurrence`，调度器和首页共同使用。后续不要在 UI 或 scheduler 中重新复制一套“下一次响铃”判断。

### PowerShell 中文乱码

部分 UTF-8 Kotlin 文件通过旧 PowerShell 输出时曾显示乱码，但 Android 模拟器实际中文正常。

不要因为终端显示乱码就直接重写源码。先使用 UTF-8 读取、IDE 或模拟器截图确认真实内容。

### Windows 文件名过长

清理 Git worktree 时曾遇到：

```text
Filename too long
```

Git 注册可能已经移除，但物理目录仍残留。处理前必须确认目标位于：

```text
D:\WakeMove\.worktrees\
```

然后使用 Windows 长路径 API 删除精确目录，最后运行 `git worktree prune`。不要递归删除项目根目录。

### 依赖和 APK 体积

Release APK 当前约 194 MB。主要体积来源包括 MediaPipe 原生库、内置 Vosk
中文模型、4 段 WAV 铃声、多个 CPU 架构的原生库和 Compose extended icons；
当前未启用代码压缩。

上架前可考虑：

- 启用 R8 / resource shrinking
- 用少量本地 VectorDrawable 替代整个 extended icons 依赖
- 检查 MediaPipe 模型资源
- 改用 AAB 交给 Google Play 按设备拆分

## 10. 新对话处理 Bug 的建议流程

每个 Bug 先收集：

1. 发生在哪个页面。
2. 精确操作步骤。
3. 预期结果。
4. 实际结果。
5. 是否每次都能复现。
6. 模拟器或手机品牌、型号、Android 版本。
7. 当时 App 在前台、后台、锁屏、刚重启还是被强制停止。
8. 截图、录屏或完整错误信息。

先复现和定位根因，再修改代码。不要把多个不相关 Bug 混在一个提交里。

建议优先级：

1. 闹钟不响、响铃被中断、无法停止、数据丢失
2. 锁屏/后台/重启可靠性
3. 动作和语音挑战错误
4. 权限与健康检查问题
5. 界面布局、文案和体验问题
